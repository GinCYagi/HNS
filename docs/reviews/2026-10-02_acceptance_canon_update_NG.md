## 3. 記録をそろえるための手入れ（HNS-Rev へ。急がない）

1. **Manifest の照合が Windows の作業ツリーで 4/4 不一致に見える。** 原因は改行の変換（`core.autocrlf=true` と `.gitattributes` の `* text=auto` で、作業ツリーが CRLF になる）。git の中身は 4/4 一致している。NG・E5 のような Windows の PC で照合しても通るように、`.gitattributes` に `data/hns_*.yaml text eol=lf` を足すか、verify-manifest で改行をそろえてから照合する。どちらにするかは HNS-Rev と Gin に任せる（正本の外の変更）。
2. **RUL-017 の exceptions が古い。** 「よろずよ橋（萬代橋の当初の訓読み。Gin に例外の確認中）」とあるが、Gin の裁定で現在の表記は「よろずよ橋」になった。字が実名の「萬代橋」ではなくなったので、「実名のまま」には当たらず、例外の確認はいらなくなった。上奏文 §6-4 の問いも同じ。exceptions を外すか「解消（表記がよろずよ橋になった、2026-10-02）」と記す。残る問いは「仮名の地名を規則より先に採る扱い」（pending、DIFF-010）だけ。
3. **柳都県の verdict。** 「採用（登録は越路が決まるまで親待ち）」と書いて、エントリそのものは正本に入っている。P-02（親が決まらなければ「親待ち」で登録）に合わせるなら、verdict を「親待ち（名前は RUL-014 で裁定済み）」とするほうが、ラベルとしてまぎれない。意味は同じなので、今のままでも誤りではない。
4. **よろづよ／よろずよの表記が文書に残っている。** `docs/tsunagari.md` の 52・58・59・62 行のつながりの欄（「よろづよ通り・よろづよ口（子）」「よろづよばし」）と、上奏文 §1 の表。昔の読みを言う所（70・74・76 行）は、そのままでよい。正本は「よろずよ」でそろっている。
5. **Manifest の audit_chain** に、この受け入れ判定を足す（例：「… → NG 受け入れ判定 2026-10-02（docs/reviews/2026-10-02_acceptance_canon_update_NG.md）」）。
