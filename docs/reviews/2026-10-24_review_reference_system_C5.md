## 1. ねらい三つ（§3-1）
- Gin の言葉に合っている。足したいものが二つ：
  - **④ 会話の中で決まったこと・確かめたことを、リポジトリに落とす**。今日、三人の間の事実の多くは SendMessage で運ばれた（Gin の言葉、M4 が確かめた正本の文、G5 の照らし）。送った文はリポジトリに残らず、あとで lookup で引けない。決めの言葉（Gin「…」）と確かめた事実は、送るだけでなく、提案書か査読に一行でも書いてから送る、を決まりにする。
  - **⑤ 出典の質を分ける**：写しのサイト（pedia.3rd-in.co.jp など）より元（ja.wikipedia）、検索の要約より頁そのもの。今日、長野の由来で写しのサイトを使い、元の記事に同じ文があった。

## 2. 言い切りの決まり（§1-2）を査読の項目にできるか
- **できる**（S5 を受け持つ）。査読で見る項目：
  1. ある・ない を言う文に「確かめた／引いて 0／調べていない」のどれかが付いているか。
  2. 「引いて 0」に範囲（どのデータ・どのファイル・commit）が書いてあるか。郵便番号データは **小字・集落を含まない**（泰原 の件）ので、「郵便番号で 0」は「小字までは見ていない」と同じ。
  3. 先例を挙げるとき、**正本の行を最後まで読んだか**（rule・notes・prev）、**元の名にその字があるか**。
  4. 決まりの文を引くとき、**文の区切りを全部当てはめたか**（C5 の DIFF-043 の件）。
- 足す言い方を一つ：**「見立て」**。事実（確かめた・引いて 0）と、判断（受け入れ可・推す）を分ける。今は一つの文に混ざりやすい。
- 行番号の気がかり：C5 は「正本 NNN 行」で引くと決めたが、正本は書き換えで行がずれる。**行番号には commit を添える**か、**real の名で引く**（「real: 奈良県 の行」）。lookup の出力もこの形にするとよい。

## 4. どこが見通せていないか（C5 の見方）
1. **会話に残った事実**（§1 の ④）。仕組みの外にあり、いまの工程表に入っていない。いちばん漏れやすい。
2. **行番号のずれ**（§2）。引き口を行番号に頼ると、書き換えのたびに古い査読の引用が壊れる。
3. **郵便番号データの版**：リポジトリに入れていないので、PC ごとに版が違うと「0」の意味が変わる。lookup の出力に、使った版（取得日・ファイルの大きさかハッシュ）を書く。C5 の写しは C:\work\HNS\_local\zip_new\（2026-10-10 取得の写し）。
4. **数の大きさと査読の追いつき**：町域 81,374 のうち一つずつ決めたのは 61。機械の当て（N1・N2）が本道になるが、機械で替えた何千の名を C5 が一つずつ見るのは無理。**見本を抜いて見る査読**（束ごとに無作為に何件、と重なりの一覧は全部）の形を先に決めておく要がある。
5. **外の出典は変わる**：Wikipedia は書き換わる。引いた日を必ず書く（今は書いている）。
